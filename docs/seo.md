# Search, AI discovery and performance

The public site is `https://danirusev.com` (apex, Bulgarian, EUR). Everything below is generated by the Worker; there is no static `robots.txt` or sitemap file.

## Indexing by host

`apps/web/src/start.ts` runs on every Worker response:

| Host                                                          | Behaviour                                                      |
| ------------------------------------------------------------- | -------------------------------------------------------------- |
| `danirusev.com`                                               | Indexable. `Strict-Transport-Security`, security headers.      |
| `www.danirusev.com`                                           | `301` to the apex with the same path and query.                |
| anything else (localhost, `*.workers.dev`, previews, Echoray) | `X-Robots-Tag: noindex, nofollow`; `robots.txt` disallows all. |

The allowed hosts live in `PRODUCTION_HOSTS` in `apps/web/src/lib/seo.ts`. Static assets are served before the Worker and do not get these headers; their caching is set in `apps/web/public/_headers`.

## Generated files

| URL              | Source                                   | Notes                                                                                                                                                                              |
| ---------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/robots.txt`    | `robotsTxt` in `lib/discovery.server.ts` | Allows all, names the major search and AI crawlers explicitly, `Content-Signal: search=yes, ai-input=yes, ai-train=yes`, disallows `/vouchers/` and `/_serverFn/`.                 |
| `/sitemap.xml`   | `sitemapXml`                             | Home, every published experience (with catalog images, `image:` sitemap) and `/contact`; `hreflang` bg-BG + x-default. No `lastmod`, since there is no reliable modification date. |
| `/llms.txt`      | `llmsTxt`                                | llmstxt.org format: summary, experiences with live prices, when to recommend the business, contact.                                                                                |
| `/llms-full.txt` | `llmsFullTxt`                            | Programs, inclusions, prices, safety, FAQ, published reviews, videos.                                                                                                              |

All four are built from the Echoray catalog (one list call; `llms-full.txt` reads details one at a time because the gateway rate-limits bursts, falling back to the bundled product files with the live list price) and cached for an hour in the colo's edge cache (`caches.default`, inactive on `workers.dev`).

Copy rule for `llms*.txt` and structured data: only facts the site itself publishes (titles, champion/stunt credentials from the about section, prices, specifications, published reviews). Do not add invented superlatives, ratings or awards; unverifiable claims are a consumer-protection risk and search/answer engines discount them.

## Page metadata and structured data

`pageMeta()` in `lib/seo.ts` gives each route a title, description, canonical, `hreflang`, Open Graph and Twitter tags. The root route adds global tags (robots directives, `geo.region=BG`, `og:locale=bg_BG`, manifest, icons, `llms.txt` alternate link) and a JSON-LD `@graph`: `Organization`/`LocalBusiness`/`SportsActivityLocation` (legal name, ЕИК, address, phone, area served), `Person` (Дани Русев), `Place` (Писта Крайници) and `WebSite`.

| Route                            | JSON-LD                                                                                |
| -------------------------------- | -------------------------------------------------------------------------------------- |
| `/`                              | `WebPage` with an `ItemList` of the experiences                                        |
| `/experience/$slug`              | `Product`+`Service` with `Offer` (price in EUR, when not on request), `BreadcrumbList` |
| `/contact`                       | `ContactPage`, `BreadcrumbList`                                                        |
| `/privacy`, `/cookies`, `/terms` | `BreadcrumbList`; text ported verbatim from the legacy pages (`src/features/legal`)    |
| `/vouchers/$token`               | none; `noindex`, `no-referrer`, never cached                                           |

No `FAQPage` or `AggregateRating` markup: there is no visible FAQ section on these pages, and Google does not show self-served review stars for a business about itself.

## Performance budget (as built)

- First load of `/` requests only the CSS, the 53 KB Latin wordmark font and the hero poster (21 KB on phones, 48 KB at 1080w). React hoists the poster preload; nothing below the fold is eager.
- Hero video starts after hydration, never for reduced motion or Save-Data; 1.7 MB on phones, 6.2 MB on desktop (was 12.85 MB HEVC that most Chrome and all Firefox installs could not play).
- Local images get `srcSet` from `media-variants.json`; experience galleries use the catalog's card/detail presets and thumbnails when Echoray returns them.
- Hashed `/assets/*` and `/fonts/*` are immutable for a year; `/media/*` and posters for 30 days.

## Launch checklist (outside the repository)

1. Cloudflare dashboard → the `danirusev.com` zone → **AI Crawl Control** / **Bots**: turn off "Block AI bots" and the managed `robots.txt`, otherwise Cloudflare blocks or rewrites the AI crawlers this site invites. Leave "AI Labyrinth" off.
2. Attach `danirusev.com` and `www.danirusev.com` to the `danirusev-web` Worker as custom domains (the www redirect happens in the Worker).
3. Google Search Console and Bing Webmaster Tools (Bing feeds ChatGPT and Copilot search): verify the domain by DNS, submit `https://danirusev.com/sitemap.xml`, and in Bing enable IndexNow.
4. Google Business Profile for "Dani Rusev 11" with the same name, phone and address as the structured data, category "Driving school"/"Race course", photos, and the booking link; ask happy customers for reviews there.
5. Test with the Rich Results Test and the Schema.org validator after deployment.
