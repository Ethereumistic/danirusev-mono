## 2. Selection, cart, checkout, and order persistence

### Selection and pricing

The add-on UI permits multiple standard extras and one location, voucher medium, and duration. It auto-selects the first location, first duration, and first free voucher (otherwise first voucher). Voucher IDs live in `additionalItems`; location and duration IDs have separate selection properties ([components/experience/experience-additional-items.tsx:44](/home/echo/Documents/danirusev/components/experience/experience-additional-items.tsx:44), [components/experience/experience-additional-items.tsx:54](/home/echo/Documents/danirusev/components/experience/experience-additional-items.tsx:54), [components/experience/experience-additional-items.tsx:95](/home/echo/Documents/danirusev/components/experience/experience-additional-items.tsx:95)).

The normal displayed unit price is:

```ts
// Sidebar filters add-ons by these selections:
selections.additionalItems.includes(itemId) || itemId === selections.selectedDuration
// Then sums item.price || 0:
const totalPrice = (hasPrice || selectedDurationItem) ? basePrice + additionalPrice : 0
```

Source: [components/experience/experience-booking-sidebar.tsx:30](/home/echo/Documents/danirusev/components/experience/experience-booking-sidebar.tsx:30). Duration prices are **added to** base price, not replacements. With no positive base price and no selected duration, the displayed price is zero / “ПО ДОГОВАРЯНЕ” even if other extras have prices. **Location selection is excluded from this sum**, despite location rows supporting a price.

A date is mandatory in the add-to-cart UI. The calendar stores a local `YYYY-MM-DD` string, disables `date < new Date()` (effectively also today's midnight), and explicitly says the preference will be confirmed by phone after purchase. There is no availability lookup or slot selector ([components/experience/experience-additional-items.tsx:251](/home/echo/Documents/danirusev/components/experience/experience-additional-items.tsx:251), [components/experience/experience-booking-sidebar.tsx:64](/home/echo/Documents/danirusev/components/experience/experience-booking-sidebar.tsx:64)). APIs only validate `selectedDate` as an optional string, so UI date requirements are not enforced server-side ([app/api/create-payment-intent/route.ts:56](/home/echo/Documents/danirusev/app/api/create-payment-intent/route.ts:56), [app/api/create-manual-order/route.ts:41](/home/echo/Documents/danirusev/app/api/create-manual-order/route.ts:41)).
